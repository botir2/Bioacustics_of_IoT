Audio PCA Trajectory Visualiser – Project Continuation Notes

Project goal
The goal of this small project is to build a Python/PyQt6 tool that visualises acoustic signals in a PCA space, similar to a protein PCA trajectory plot. Instead of protein conformations, the system uses audio features extracted from bird/no-bird recordings. The long-term idea is to create a reference acoustic map from a labelled dataset, then place new WAV files or live microphone input into that map as moving points or trajectories.

10. Important real-time design rule

The system should not fit PCA in real time.

Correct approach:
Dataset feature map
→ fit StandardScaler once
→ fit PCA once
→ use these fitted objects for real-time transform

Real-time input:
Microphone audio
→ extract feature vector
→ scaler.transform()
→ pca.transform()
→ plot point

This makes the system fast enough because only feature extraction and PCA transform are done during live operation.

11. Microphone error encountered

During testing, this error appeared:

Mic error: Error opening InputStream

This usually means one of the following:
- the selected microphone index is not valid
- the selected backend does not support the chosen sample rate
- another app is using the microphone
- Windows microphone permission is disabled
- the selected device is an output device, not an input device
- WDM-KS backend is not behaving well with sounddevice

Troubleshooting steps:
1. Press STOP MIC before changing devices.
2. Try another microphone from the dropdown.
3. Start with MME or DirectSound devices.
4. Avoid Stereo Mix, Speakers, and PC Speaker devices.
5. Try MIC_SR = 44100 first.
6. If 44100 fails, try MIC_SR = 48000.
7. Close Teams, Zoom, browser tabs, or other apps that may be using the microphone.
8. Check Windows microphone permission:
   Settings → Privacy & security → Microphone
   - Microphone access should be ON
   - Let desktop apps access your microphone should be ON

12. Code change made for microphone selection

The earlier version used a fixed microphone index such as:

MIC_DEVICE_INDEX = 24

This was replaced with a GUI dropdown-based device selector.

The program now uses:

selected_device = self.mic_combo.currentData()

and then records audio using:

audio = sd.rec(
    int(MIC_DURATION * MIC_SR),
    samplerate=MIC_SR,
    channels=1,
    dtype="float32",
    device=selected_device
)

This allows the user to select different system microphones without manually editing the code.

26. Meaning of the extracted feature values

The values in features_map.csv and features_map_with_silence.csv are not random. Each row is one audio file converted into an 18-dimensional feature vector.

The columns mean:

f0 = RMS energy
f1 = zero-crossing rate
f2 = spectral centroid
f3 = spectral bandwidth
f4 = spectral rolloff
f5 to f17 = MFCC 1 to MFCC 13

Interpretation:
- RMS energy represents signal strength.
- Zero-crossing rate describes how often the waveform crosses zero.
- Spectral centroid represents the brightness or centre of mass of the spectrum.
- Spectral bandwidth represents how spread out the frequencies are.
- Spectral rolloff represents the frequency below which most spectral energy is located.
- MFCCs represent the spectral/timbre shape of the sound.

Pipeline:

WAV audio
→ librosa feature extraction
→ 18 feature values
→ PCA reduces 18D to 2D
→ Random Forest or another classifier can later use the same 18 features for prediction
